# Bilap Connect — MVP starter

واجهة مراسلة مغربية بهوية الزليج، HTML/CSS/JavaScript + ASP.NET Core (C#).

## المتطلبات
- .NET 8 SDK أو أحدث متوافق مع المشروع.
- حساب لدى مزود SMS يدعم إرسال والتحقق من OTP. المثال مهيأ لـ Twilio Verify.
- هاتف أو متصفح حديث.

## تشغيل محلي
1. ثبّت .NET SDK على الحاسوب أو بيئة التطوير.
2. ادخل مجلد `server`.
3. أنشئ مفتاح JWT عشوائياً بطول 32 بايت على الأقل، ثم عيّن المتغيرات:
   - `Jwt__Key` (سر عشوائي قوي، لا تضعه في Git)
   - `Twilio__AccountSid`
   - `Twilio__AuthToken`
   - `Twilio__VerifyServiceSid`
4. شغّل:
   ```bash
   dotnet restore
   dotnet run
   ```
5. افتح عنوان الخادم الذي يظهر في الطرفية. ملفات الواجهة موجودة في `server/wwwroot`.

## ملاحظات SMS
- خدمة Twilio Verify قد تحتاج حساباً مفعلاً، رصيداً، والتحقق من أرقام الوجهة في حسابات التجربة. راجع أسعار المغرب والقيود الحالية لدى المزود قبل الاستخدام.
- لا توجد رموز SMS وهمية: إذا لم تضبط بيانات Twilio الصحيحة، سيرفض الخادم طلب التحقق برسالة إعداد واضحة.
- لا تضع مفاتيح Twilio أو JWT في HTML أو JavaScript أو مستودع عام.

## ما الذي يحتويه هذا النموذج؟
- طلب OTP والتحقق منه عبر Twilio Verify.
- JWT للمستخدم بعد التحقق.
- SQLite لحسابات المستخدمين والرسائل.
- SignalR لإرسال واستقبال الرسائل الفورية.
- واجهة عربية RTL متجاوبة بتصميم زليج مستوحى من المغرب.

## حدود النموذج قبل الإطلاق العام
هذا MVP تعليمي وليس جاهزاً للإنتاج دون مراجعة أمنية. قبل إطلاقه:
- أضف سياسة خصوصية وشروط استخدام وحذف الحساب والبيانات.
- اضبط CORS على نطاقك فقط، وفعّل HTTPS دائماً.
- أضف CAPTCHA أو حماية إساءة استخدام مناسبة، وحدود إرسال OTP لكل رقم وعنوان IP، ومراقبة تكاليف SMS.
- راجع صلاحيات المحادثات، وسجل التدقيق، والنسخ الاحتياطي، والهجرة إلى قاعدة بيانات إنتاجية.
- SignalR هنا يتيح الرسائل المباشرة، لكنه لا يوفر تشفيراً شاملاً بين الطرفين (E2EE).
- لا تستخدم أرقاماً أو بيانات حقيقية في الاختبارات العامة.

## النشر
انشر تطبيق ASP.NET Core على خدمة تدعم .NET وHTTPS، مع تخزين دائم لقاعدة البيانات أو PostgreSQL مُدار. عيّن المتغيرات السرية من لوحة الاستضافة. لا تعتمد على نظام ملفات مؤقت لتخزين SQLite في بيئة قد تمسح الملفات عند إعادة التشغيل.
